03

Đã lược bỏ & vì sao

Chỉ cắt field/tính năng cụ thể — 4 màn hình vẫn tách biệt như hệ thống thật.

Field/tính năng không code

  • Selling Zone: Company, Sales Organization Structure — chỉ giữ region/province/ward trực tiếp.
  • Route Master: GPS Lock/Distance/GPS Out Route Lock/Minimum Visit Time, tab Check-in Schedule, tab List Of Company.
  • Route Setting: Coverage Outlet Quantity / Potential Outlet Quantity (cần logic tính KPI riêng).
  • Cả hệ thống: Branch User Assignment (đồ án dùng chung 1 cấp Role, không phân quyền theo chi nhánh).
Duy nhất 1 màn hình bỏ hẳn: MCP Adjustment — đổi salesman/thời gian thì sửa trực tiếp trên route_setting, không tạo bản ghi điều chỉnh + workflow duyệt riêng.
04

Việc cần code

Theo đúng pattern đã làm mẫu ở backend/.../auth/ + backend/.../user/ — entity/repository/service/controller/dto.

Entity JavaBranch (backend/.../branch/), SellingZone/RouteMaster/RouteSetting (backend/.../route/{sellingzone,routemaster,routesetting}/) — khung folder rỗng đã có sẵn
Repository + Service + ControllerCRUD cho cả 4; thêm 1 endpoint riêng gán/gỡ khách hàng khỏi Route Master
Frontend UI4 trang /branches, /selling-zones, /route-masters, /route-settings đã có placeholder + menu Ant Design "Tuyến bán hàng" — chỉ cần thay UI thật vào
Cập nhật API contractThêm endpoint mới vào docs/05-api-contract/api-endpoints.md khi code xong

Bản rút gọn dựa trên khảo sát nghiệp vụ Route/MDM thật của hệ thống DMS (Branch, Selling Zone, Route Master, Route Setting, MCP Adjustment) — giữ nguyên cấu trúc màn hình, chỉ cắt field không cần đi sâu. Dùng nội bộ cho đồ án ERPQLKHO, không phải tài liệu chính thức của nhà cung cấp phần mềm.
